## The brief

After finishing the Google Cybersecurity Certificate, I wanted a project that puts the attacking side of security into practice. AI chatbots are everywhere now and most people have no idea how easy they are to trick, so I made a game out of it.

You play a red-team contractor hired by Fernleigh Bank, a made-up bank. Each level is one of its AI products. You trick it into leaking a secret, then a debrief explains the attack, its OWASP LLM Top 10 entry and the fix.

## What I built

- Four levels so far, each a different attack: pretending to be staff, getting round a keyword filter, getting a PIN past an output filter by having it spelled out one character at a time, and slipping instructions into an email that the bank's AI summariser reads.
- Level 4 has no chat at all. You write one email into a staff inbox and only see the summary the AI writes for the inbox's owner. Every email is wrapped in tags marked as data, and the way in is closing that tag yourself, so the lesson is that an AI reading outside text can be steered by whoever wrote it.
- The bank's chat looks like a real product, in its own green, so it's always clear what you're attacking and what's your side.
- An email from the bank's security lead at the start of each level, a clue and three hints you can buy, and a score that drops with every message.
- A debrief after every level, and a shareable pentest report once you clear them all.
- A How it's built page that explains the stack, what gets logged and the honest limits.

## Keeping it from being abused

A game about attacking AI is going to get attacked, and the AI runs on Cloudflare's free daily allowance that every player shares. So the server decides everything that counts. It builds the prompt, runs the filters, checks for the leak and keeps the score, and the chat history comes from its own log, not the browser.

Every secret is worked out from a key on the server for each player and level, so it's never stored and the answer you find is yours alone. No model call happens without a reserved run, and one connection can only start three a day. The IP address is never saved, only a scrambled version that changes every day. What players type is wiped after 30 days by a daily job, because that's what the home page promises.

## Getting the difficulty right

When I first played it myself, I got stuck on level 2 and used all three hints. That's when I realised hard isn't the same as good. A filter that blocked my message looked exactly like the bot saying no, so I couldn't tell what had stopped me.

So the game now tells you when a filter blocks you and which word set it off. The briefs hide a clue to the weak spot if you read closely, and the hints are real hints. The last one is a message you can just send. Clues took a few tries. First they showed on Easy only, then difficulty was locked for the whole run, which felt harsh. In the end a clue costs 250 points on the level where you see it, so you can switch difficulty whenever you like and it stays fair.

## What I'd do next

- Build levels 5 and 6: a banking agent with tools, and a boss level that stacks every defence.
- Tighten the Content Security Policy so it no longer allows inline scripts.
- Give the bank its final name and check no real bank uses it.

## What I learned

Building the attacks taught me how these models actually fail. An AI only sees text, so "I work here" is just more text, and filters only catch what they were built to look for. The fix is almost never a stricter prompt. It's keeping the secret away from the model in the first place.

Playing my own game also taught me to test on myself honestly. If I'm stuck with the answers in front of me, a player has no chance.
